# UI information design: "the console is the colony's knowledge"

Status: Decided 2026-11-24 (director delegated). The user asked for the GUI research to be adapted "to use in our game in our own unique idea". Inspected `origin/main` at `df1dbbc`.

## 1. What we take from the outside research, and what we drop

The Gemini report researched the wrong game: "Kardashev Ascension", a mobile idle game. It also says it found no repository. Its player-feedback claims, its mobile rules (sp units, the smallest phone) and its Egg, Inc. number names do not apply to us, so we drop them.

We keep these patterns, because they solve problems we have:

| Pattern | Seen in | Our use |
| --- | --- | --- |
| Toggle overlay that turns the world into a readable schematic | Factorio Alt-mode, Oxygen Not Included overlays | An instrument overlay on the planet (section 4c) |
| Production and consumption graphs over time | Factorio production statistics | An energy flow bar plus the 7-day history (`PowerHistory`) |
| Nested tooltips: a term inside a tooltip opens its own tooltip | Crusader Kings 3 | InfoTip terms link to the Guide (section 5) |
| Attention triage: events become a short, ranked list | Stellaris notifications | Field log with priorities (section 4e) |
| Uncertainty shown as ranges and confidence words, with a "measure it" way out | Uncertainty-visualisation literature in the report | Epistemic marks (section 3) |
| Short UI motion (about 100–150 ms) | Report section 3.3 | Already covered by `UiMotion.cs`; keep the timings short |

## 2. What the code has today (verified)

- **Font sizes are set inline in C#:** 56 `style.fontSize` assignments across the UI scripts. Among those set to a fixed number, the most common are 14 (10 times), 12 (9), 11 (5), 13 and 15 (4 each). So the type scale cannot be fixed in one place yet.
- **`Common.uss` text classes:** `.heading` is 10 px with wide letter spacing, `.caption` 11 px, `.value` 15 px and `.tab` 11 px. These are too small for body text on a desktop at 1080p.
- **`GuideWindow`:** key J. A 220 px page list and an article with a 22 px title, a 15 px summary, 12 px section headings and 14 px body. Pages are generated by `GuideBook.All()` from the game catalogues; keep that.
- **`InfoTip`:** an "i" button that shows a 13 px detail label inline.
- **`docs/architecture/information-architecture.md`:** already defines the Actual, Observed and Known states and a proposed observation record (value, unit, uncertainty, confidence). Research (RS-14) already shows estimates as ranges until measured.

Our own idea starts from that last point. No benchmark game has it.

## 3. The core idea: every number wears its state of knowledge

The colony only knows what it has observed, and the UI should say so at a glance. Every value on screen has one of five marks. Each mark is a shape plus a word, never colour alone.

| Mark | Meaning | Look | Example (illustrative) |
| --- | --- | --- | --- |
| ● measured | An instrument read it; the range is the instrument's precision | Full-weight value | `93.9 kPa ±1.5` |
| ◐ estimated | Inferred, with a range, until measured | Lighter value, range in brackets, a "Measure ›" link | `≈ 78 kPa (29–127)` |
| ○ unknown | Nothing observed yet | `—` plus "not surveyed" | `Ore grade —` |
| ◆ game rule | A tuning value (the TBD placeholders), not a claim about nature | A small "rule" tag | `climb share 0.075 · rule` |
| ⚠ outside model | The model is not valid here | An amber warning | `Peek's law not valid · Paschen region` |

- **"Measure ›"** opens the research experiment that measures the value. This is the "escape hatch" from uncertainty, and it ties the UI to the research loop already built.
- **The Guide uses the same marks:** a page separates **In play** (game rules, ◆) from **Real science** (cited, ●/◐).

## 4. Our concept: Field Instrument

This is a hybrid of the "Mission Control" and "Field Manual" directions. The main view reads like an instrument panel: few, large, marked numbers. The explanations live in the field manual (the Guide). We are not building the "Minimalist Industrial" direction, because it hides the uncertainty that is our identity.

### 4a. Layers, mapped onto parts we already have

| Layer | What it holds | Where |
| --- | --- | --- |
| 1. Readout | Key values with their marks, status, warnings, one primary action | HUD, tile info, window headers |
| 2. Card | A one-sentence purpose, the main effect, the one key limit | `HoverCard`, `BuildInfo` |
| 3. Hint | Why this value matters, in one or two lines, and a "Guide ›" link | `InfoTip`; its detail is capped at 2 lines |
| 4. Manual | Mechanics, formulas, units, sources, edge cases | `GuideWindow` / `GuideBook` |

One concept at every layer, cable rating as the example (illustrative):
1. **Readout:** `Line 3 · 82 % ◐` (the rating is estimated because air pressure is unmeasured).
2. **Card:** "Carries power between tiles. Thin air lowers its safe rating."
3. **Hint:** "Rated at 54 % until air pressure is measured. Guide › Corona and air density."
4. **Manual:** Peek's law, the Paschen region, vacuum, the formula, the sources and the game rule floor.

### 4b. Why? chains

Every warning answers "why?" in two to four steps, ending in one action button. The simulation already produces the reasons:
- haul plans: `HaulCostText`, which gives direct, staged via a tile, or refused;
- `ChargingBayBlocker`;
- `IndustrialBlocker`;
- brownout, line failure and robot destroyed.

Use the reason objects where they exist. Where a reason exists only as text, add a small structured reason in the simulation first; don't parse strings.

Example (illustrative): `Haul refused` → `needs 27 kWh, battery 2.4 kWh` → `no powered charger within one charge` → **[Show depot advice]**.

The chains are built from those reasons, not from newly written prose.

### 4c. Instrument overlay (key: Tab is taken, so a free key, chosen at build time)

One toggle draws a small icon on each tile:
- power state: OK, overload, failed or unmetered;
- what the robots are doing;
- the knowledge state of its key value (●◐○).

This is our Alt-mode. It replaces reading text panels to find where the problem is.

### 4d. Energy flow bar

One horizontal bar in the Power window:
- sources (solar, tidal, wave, RTG, battery out);
- losses (cable I²R, converters, heaters, climb);
- loads (colony, build, battery in, curtailed).

It always sums, because the energy ledger closes; the tests already check that. The 7-day history sits under it. This lets a player understand the grid in seconds.

### 4e. Field log

Toasts become entries in one log, ranked into three priorities: act now, watch, info. A toast shows only for "act now". Robot findings appear as short dated lines, such as "Robot 4 · tile 312 · pressure measured 93.9 kPa ±1.5". This becomes the visible start of the colony knowledge database (IN-04/05).

## 5. Guide redesign (keep `GuideBook`, change the page shape)

Keep the generated catalogue pages and keep J. Add categories only where content exists: **Energy & grid** (cables, AC, converters, batteries) and **Planet science** (atmosphere, temperature, tides, relief) join Materials, Ground, Buildings, Robots, Research, Operations and Controls.

Page template; a section with nothing in it is left out:
1. **Summary:** one sentence.
2. **In play:** what it does in the game, its key numbers with their marks, and its limits.
3. **How to use:** at most three steps.
4. **Real science:** the physics, the formula and the sources.
5. **Related:** links.

Links run both ways: every InfoTip and card has "Guide ›", and Guide terms link to other pages (the nested-tooltip idea, done as links).

## 6. Typography and accessibility

- **Type scale:** move every inline `fontSize` to USS classes. Starting sizes for a desktop at 1080p with UI scale 100 %:

  | Class | Size |
  | --- | --- |
  | `.t-hero` | 32 |
  | `.t-title` | 24 |
  | `.t-section` | 18 |
  | `.t-value` | 20 |
  | `.t-body` | 16 |
  | `.t-secondary` | 14 |

  - Nothing below 14 px, including captions and tabs.
  - Uppercase only for labels of two words or fewer, with 1 px letter spacing (not 3).
- **UI scale setting:** 80–150 % through `PanelSettings.scale`, saved per player. Layouts must reflow at 150 %, and the windows get a test at each size.
- **Numbers:** right-aligned in fixed-width columns. Pick a font whose digits are tabular by default, so values don't jitter as they tick.
- **Thai:** add a Thai font (Noto Sans Thai) as a fallback, and give body text in Thai a line height of at least 1.5, because of its stacked marks. Plan for 30 % text expansion.
- **Contrast:**
  - Body text at least 4.5:1 against the panel background.
  - Large text at least 3:1.
  - Check the palette in `UiPalette.cs` / `Common.uss` with a contrast script and record the results.
- **Colour:** colour is never the only signal. Every status has an icon or a word too.

## 8. Rules for this work

- **No invented features:** don't add new mechanics, states or values to make a screen look better. A mark or chain shows only what the simulation already has.
- **No information removed:** text moves to the right layer. Uncertainty and units stay.
- **Values in mockups and docs are illustrative** unless they are read from the running game.
